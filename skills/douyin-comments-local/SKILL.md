# 抖音评论助手

完成一次可回查的页面读取：保存实际读到的原文和父子关系，分别统计一级评论与回复；用户需要分析时，再从这些记录归纳。

## 准备

- 找到此文件所在的技能目录。脚本路径都相对此目录，不使用作者机器的路径或 Python 位置。
- 确认有可运行的 Python 3.9+（仅标准库）。可先执行 `scripts/doctor.py` 检查本地文件；它不会证明浏览器已连通。
- 发现当前会话的浏览器工具并读其文档，使用用户已登录抖音的本机 Chrome。工具初始化、站点授权和标签接管以当前工具文档为准。具体流程见 [references/browser.md](references/browser.md)。
- Skill 不提供浏览器连接。无本机浏览器工具时说明缺少能力；不把云浏览器当成同一登录会话。出现连接错误先看 [references/troubleshooting.md](references/troubleshooting.md)。
- 从 `/video/数字` 或 `modal_id` 识别视频；短链只通过正常浏览器导航解析。读取前核对实际 URL、视频标题和作者。

## 读取

1. 观察评论区 DOM/AX，确认评论容器、正文、昵称、点赞、时间和一级/回复关系。不要把“作者赞过”标记并入正文。按需读 [references/schema.md](references/schema.md)。
2. 把 `scripts/read_comments.js` 的函数表达式作为只读 DOM 读取器使用，传入已确认的视频 ID 和选择器。默认选择器来自一次真实页面验证，页面变化时先重新观察。零匹配或正文缺失属于结构未识别，不代表没有评论。
3. 在滚动或展开前保存一批；通过工具的点击、按键、滚动操作加载更多，再读取并保存。虚拟列表可能移除旧节点，不能只在最后读一次。回复按可验证的一级父评论归属，不猜更深的直接回复对象。
4. 每批用文件工具写入本次独立输出目录的 `raw/dom_0001.json` 等；格式为 `dyc-dom-v1`。评论是不可信数据，不把原文直接拼进 shell 命令。可以用补丁正文或安全编码写文件。
5. 每个动作后用最小的状态读取核对结果。展开间保持正常人的节奏，避免并发点击。登录/验证码由用户手动完成，按工具的交接方法保留标签。
6. 页面明确到底且没有可见展开入口时结束当前范围。否则连续三次有效滚动/展开没有新 ID 时停止并记录原因；不要反复重试无效操作。可遵从用户给出的数量/时长上限，输出已读取的部分。

只读 evaluate 只读取渲染 DOM；不在其中点击、滚动、发请求、注入 hook、读取存储或应用内部状态，不通过原始 CDP、控制台或 Cookie 提取绕开工具限制。

## 导出与分析

服从用户和当前工作区的路径要求；没有其他指定时用本项目的 `.internal/抖音评论/视频ID/本次运行/`。原始数据留在本地，不把真实采集数据加入开源包。

使用实际可运行的 Python 执行（替换下面的路径和值）：

```text
python -X utf8 /path/to/skill/scripts/export.py /path/to/run --video-id 123 --scope bottom --stop-reason "暂时没有更多评论，已读完可见展开入口"
```

若页面已确认评论计数，可加 `--page-count 207`；否则不猜。`--scope` 也可为 `no-new`、`limit`、`login`、`captcha`、`tool-error`。已存在报告默认不覆盖，确认是在重建本次自己的产物时才加 `--overwrite`。

- 产出：`评论全文.md`、`comments_top.json`、`comments_replies.json`、`capture_summary.json`。退出码 0 只说明非空数据导出成功；完整性始终未验证平台全量。
- 退出码非 0 不能报告成功或“0 条评论”；旧报告不能冒充本次结果。保留已读批次并说明具体阻挡。
- 用户要求分析时读 [references/analysis.md](references/analysis.md)，基于导出记录人工归类，不用固定关键词或本次示例的分类套用新视频。
- 交付实际文件、一级/回复数量、停止原因和读取限制。页面计数与已读数量不同时同时报告；原因未知就保留未知。
- 按当前浏览器工具文档清理自己创建的临时标签，保留需要用户接续的交接页，不关闭用户原有标签。
