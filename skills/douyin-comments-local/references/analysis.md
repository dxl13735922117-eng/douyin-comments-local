# 基于已读评论分析

分析前核对导出成功且非空。每条保留 `cid`、`parent_cid`、原文、层级和来源；不能用虚构样例补足读取失败或未加载的评论。

## 默认分类

- **质疑**：对实际价值、差异、成本、可靠性或推荐真实性的保留、否定或反问。评论提出质疑不等于已经证实。
- **疑问**：寻求事实、操作路径、效果或解释。与质疑可重叠。
- **使用经验**：陈述自己或可明确识别的使用过程、产出、限制或体验。泛泛好评不自动视为真实使用；其他产品的体验需单独标明对象。
- **产品建议**：具体提出功能、架构或工作流改进。若把用法建议纳入此类，明确显示“产品及用法建议”；讽刺性建议、购入推荐不要误标为功能需求。
- 不适合四类的解释、互动、纯好评或旁支归为“其他”，不强行归类。

采用多标签时明确数量不能相加为独立评论或人数。分别统计一级和回复；作者回复单独标记，计算观众关注点时可排除作者并说明口径。主题按语义标注，不用固定关键词替代阅读。

## 避免误读

- 阅读父楼与相邻回复，识别指代；不能确定对象的“封号”“很贵”“不行”等保留歧义。
- 错字与随后更正保留各自原文；重复发布但不同 ID 的记录保留，不把它们当成独立用户。
- 把实际体验、作者自述、未经验证的技术/价格说法、玩笑和分析者推导分开。
- 不把别的产品的耗费、封号或效果归到视频中的产品。作者回答也不自动成为官方事实。
- 归纳“最关心”要有反复出现或互动支持；提供主题计数时说明是评论条数、可多标签、当前样本，不是总体问题发生率。
- 产品改进方向若由评论推导，明确写“由评论归纳”，不要包装成观众原话或已验证方案。

## 交付

在原始导出之外，可创建 `comments_classified.json`（逐条标签、主题、归类理由或歧义说明）、`评论分类明细.md` 和 `评论分析报告.md`。报告包括范围、分类计数、主要关切、代表原文、相反意见及未解决问题。引用真实已读记录，按需要隐藏昵称；开源包中不附带用户真实采集数据。
